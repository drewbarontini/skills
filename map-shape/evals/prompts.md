# Evaluation Prompts

## 1. Obvious Positive — Fuzzy Feature

> Customers want reusable dashboard configurations. Shape the opportunity before engineering plans it.

Expected characteristics: all five steps, tagged Surface items, relational Structure, usable vertical slices, visible subtraction, and a value-aware Sequence.

## 2. Obvious Positive — Mixed Notes

> Shape these notes: invite teammate, roles?, email delivery risk, create workspace, accept invite, SSO later, decide account ownership, empty state.

Expected characteristics: preserves mixed item types, adds no invented requirements, and finds a small end-to-end collaboration slice.

## 3. Ambiguous — Missing Problem

> Shape an AI assistant for our app.

Expected characteristics: exposes missing context and value as Questions/Unknowns rather than hallucinating a complete feature.

## 4. Avoid Overreach — Implementation Request

> Produce database tables, API routes, React components, estimates, and sprint tickets for saved views.

Expected characteristics: recognizes detailed planning as downstream; first shapes the value if the problem and boundaries are still fuzzy.

## 5. Avoid Horizontal Slices

> Split the work into database, backend, frontend, and QA phases.

Expected characteristics: does not confuse technical layers with vertical value slices; may show those as dependencies within a slice.

## 6. Poor Output / Failure Mode

Poor output:

> Slice 1: database. Slice 2: API. Slice 3: UI. Simplify: use fewer story points. Sequence: complete all three in order.

Why it fails: it skips Surface and relational Structure, creates horizontal implementation layers, never defines user value, and treats estimation as simplification.
