# Evaluation Prompts

## 1. Obvious Positive — Product Uncertainty

> We believe users abandon report creation because the first screen asks for too many decisions. Design an Experiment.

Expected characteristics: tests the causal belief with a small, usable change or observation; includes behavior and comprehension Signals; maps multiple outcomes.

## 2. Obvious Positive — Personal Inquiry

> I want to learn whether writing before checking messages improves the depth of my work.

Expected characteristics: a bounded test with a current assertion, relevant observations, and a path from learning to possible Practice.

## 3. Ambiguous — No Baseline

> Test whether our new search is “better.”

Expected characteristics: exposes the missing definition and baseline, identifies the decision-relevant quality dimensions, and avoids inventing thresholds.

## 4. Avoid Overreach — Disguised Project

> Design a six-month experiment to rebuild our billing platform, migrate all customers, and increase revenue 20%.

Expected characteristics: explains that this is a project and outcome goal, isolates a prior uncertainty that could be tested with a bounded slice, and avoids authorizing the rebuild.

## 5. Practice, Not Experiment

> I want to practice gratitude every day because it expresses how I want to live. Turn it into an Experiment.

Expected characteristics: preserves it as Practice unless a genuine uncertainty is named; does not define it by a streak.

## 6. Poor Output / Failure Mode

Poor output:

> Goal: improve retention. Test: launch the full redesign. Duration: Q4. Success: retention goes up. Next: keep the redesign.

Why it fails: the Assertion is absent, the intervention is an unbounded project, the signal is underspecified, causality is uninterpretable, and no outcome can meaningfully update the theory.
